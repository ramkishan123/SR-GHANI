# Ghani Oil Management App - Complete Development Specification

## Project Overview
Create a comprehensive customer management application for a traditional ghani (oil press) business using **Flutter**. The app must support **Android, iOS, Windows** with **web debugging capabilities**.

---

## Platform Requirements
- **Primary Platforms**: Android, iOS, Windows (Desktop EXE)
- **Debug Platform**: Web (for testing purposes only)
- **UI/UX**: Premium, modern design with fully responsive layouts optimized for mobile, tablet, and desktop screens
- **Offline Support**: Full offline functionality with automatic sync when network is restored

---

## Database Requirements
**DO NOT USE ISAR DATABASE**

Instead, use one of these cross-platform alternatives:
- **Recommended Option 1**: **Hive** (lightweight, fast, works on Android, iOS, Windows, and Web)
- **Recommended Option 2**: **Drift (formerly Moor)** (SQL-based, cross-platform support)
- **Recommended Option 3**: **SQLite with sqflite_common_ffi** (for desktop) + **sqflite** (for mobile)

**Important**: Ensure the chosen database solution has full compatibility with web debugging and doesn't cause compilation issues on web platform.

---

## Authentication System

### Registration & Login
- **Authentication Method**: Email and Password ONLY
- **No Social Logins**: No Google, Facebook, or other third-party authentication
- **Pages Required**:
  - Registration page with email and password fields
  - Login page with email and password fields

## Customer Management Features

### Add Customer Form
**Required Fields**:
- Customer Name (Required, text input)
- Date and Time (Auto-populated with current date/time, editable)

**Optional Fields**:
- Mobile Number (Optional, numeric input)
  - Always prefixed with Indian country code: **+91**
  - Format: +91 XXXXXXXXXX
- Address (Optional, text area input)

### Seed Management (Multi-Entry System)

**Default Seed Options**:
1. Til (Sesame)
2. Mungfali (Peanut)
3. Black Sarso (Black Mustard)
4. Yellow Sarso (Yellow Mustard)
5. Coconut

**Features**:
- Users can add custom seed types beyond the default list
- Each customer can have multiple seed entries (same or different seeds)
- Example: Customer A can have:
  - Til: 20 kg
  - Til: 15 kg (separate entry)
  - Mungfali: 30 kg
- Each seed entry should include:
  - Seed type (dropdown with defaults + custom options)
  - Weight/Quantity (in kg)
  - Individual status tracking

### Status Workflow

**Three Status Levels**:

1. **Pending**: Initial status when customer is added
2. **Completed by Us**: When ghani processing is finished
   - Mark entire customer order or individual seed entries as completed
3. **Fully Completed**: When customer collects their oil/khali

### Payment Collection System

When marking order as **Fully Completed**, user must select payment method:

**Payment Options**:
1. **UPI** - Digital payment
2. **Cash** - Cash payment
3. **Khali** (Oil cake leftover after extraction)
   - If Khali is selected, trigger conditional logic:
     - **For Mungfali (Peanut)**: Show input field "Extra charge: ₹5 or custom amount"
     - **For Til (Sesame)**: Only accept Khali as payment (no extra charge)
     - **For Mixed Orders (Khali + Oil taken by customer)**: Charge ₹20 per kg

**Payment Tracking**:
- Store payment method with timestamp
- Allow viewing payment history per customer
- Calculate total revenue by payment method

## Firebase Integration & Real-Time Sync

### Firebase Services Required:
1. **Firebase Authentication**: For user login/logout
2. **Cloud Firestore**: For real-time data synchronization
3. **Firebase Storage**: If needed for any file uploads (PDFs, images)

### Data Structure (Firestore):
```
users/
  └── {userId}/
      └── customers/
          └── {customerId}/
              ├── name: String
              ├── mobileNumber: String (optional)
              ├── address: String (optional)
              ├── dateTime: Timestamp
              ├── status: String (pending/completed_by_us/fully_completed)
              ├── paymentMethod: String (optional)
              ├── createdAt: Timestamp
              ├── updatedAt: Timestamp
              └── seeds/
                  └── {seedId}/
                      ├── seedType: String
                      ├── quantity: Number (kg)
                      ├── status: String
                      └── createdAt: Timestamp
```

### Real-Time Sync Behavior:
- **Add Customer**: Instantly sync to Firestore → all devices update in real-time
- **Edit Customer**: Any edit propagates to all logged-in devices immediately
- **Delete Customer/Seed**: Deletion reflects across all platforms instantly
- **Offline Mode**: 
  - Queue all add/edit/delete operations locally
  - Use Firestore offline persistence
  - Auto-sync when internet connection is restored
  - Show sync status indicator (synced/syncing/offline)

### Conflict Resolution:
- Use Firestore's last-write-wins strategy
- Optionally implement timestamp-based conflict resolution

## Advanced Settings Section

### 1. Mobile Number Scraper
**Purpose**: Extract all customer mobile numbers to prevent forgetting anyone

**Options**:
- **Download Raw Numbers**: Plain text file with numbers only
  - Format: One number per line (+91XXXXXXXXXX)
  - File name: `customer_numbers_YYYY-MM-DD.txt`

- **Download Numbers with Names**: Formatted list
  - Format: "Customer Name - +91XXXXXXXXXX"
  - File name: `customer_contacts_YYYY-MM-DD.txt`

**Export Options**:
- Download as TXT file
- Copy all to clipboard
- Share via platform share dialog

**Implementation**:
- Filter out customers without mobile numbers
- Remove duplicates if same number exists multiple times
- Sort alphabetically or by date added

### 2. Factory Reset / Data Wipe
**Purpose**: Complete data reset for logged-in user only

**Confirmation Flow**:
1. User clicks "Factory Reset" in Advanced Settings
2. Show warning dialog:
   - "⚠️ WARNING: This will permanently delete all your customer data, seeds, and payment records. This action cannot be undone."
   - "Type 'DELETE' to confirm"
3. Require text confirmation input
4. Show final confirmation: "Are you absolutely sure?"
5. On confirm:
   - Delete all Firestore data under user's collection
   - Clear local database
   - Show progress indicator
   - Logout user automatically
   - Return to login screen

**What Gets Deleted**:
- All customers and their data
- All seed entries
- All payment records
- Custom seed types added by user
- Local cache and offline data

**What Remains**:
- User authentication credentials (can still login)
- App settings/preferences (if any)

**Safety Features**:
- Require re-authentication before allowing factory reset
- Send confirmation email after reset
- Option to export data before reset

## Firestore Security Rules Example

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

This ensures users can only access their own data.
